# /monthly — 月次サイクルを回す

引数：`<クライアント名> <YYYY-MM>`
例：`/monthly 焼肉店A 2026-09`

`CLAUDE.md` の共通ルールに従います。進行役は `production-director` です。

---

## 0. 引数の確認

- 引数が足りない場合は、`10_クライアント/` のフォルダ一覧を出して、どの会社の何月かを聞く。
- クライアント名にスペースが入っている場合は、フォルダ名を確認して聞き返す。
- 対象月は「**データの月**」。9月の実績なら `2026-09`。

## 1. 会話の混線チェック（最初に必ず）

この会話で既に別のクライアントを扱っていた場合は、**作業を始めずに**次を伝えて止まる。

```
この会話では既に「（別の会社名）」を扱っています。
情報が混ざるのを防ぐため、/clear を入力してから、もう一度 /monthly を実行してください。
```

## 2. 前提チェック

| 確認するもの | 無いときの動き |
|---|---|
| `10_クライアント/<名前>/` | 止まる。フォルダ一覧を見せて名前を確認 |
| `基本情報.md` | 止まる。「基本情報が未作成です」と伝え、作成を提案 |
| `効いた型.md` | 無ければテンプレートから作って続行 |
| `データ/` に対象月のインサイト | 止まる。「データ未配置です」と置き場所を伝える |
| `データ/` に対象月の広告データ | 無ければ広告工程を「―（対象外）」にして続行 |
| `05_月次管理/YYYY-MM.md` | 無ければ `90_テンプレート/月次管理表.md` から作る |

## 3. 再実行かどうかを判断する

`05_月次管理/YYYY-MM.md` にその会社の行があり、`済` の工程がある場合は**やり直さない**。
`未` の工程だけを実行する（利用上限で途中終了した場合に、続きから再開できるようにするため）。

すでに全工程が `済` の場合は、その旨を伝えて「作り直しますか？」と聞く。

## 4. 作業リストを見せて合意を取る

実行する工程・使うデータファイル・所要時間の目安を表で見せ、「これで進めますか？」と聞く。
承認が得られてから実行する。

## 5. 実行

管理表のセルを、着手時に `作業中`、完了時に `済` へ更新しながら進める。

| 順番 | エージェント | 出力 | 備考 |
|---|---|---|---|
| 1 | `instagram-analyst` | `分析/YYYY-MM_分析.md` | |
| 2 | `ad-operator` | `広告/YYYY-MM_広告.md` | 広告データが無ければスキップ（`―`） |
| 3 | `competitor-researcher` | `リサーチ/YYYY-MM_競合.md` | |
| 4 | `content-planner` | `企画/<翌月>_企画.md` | 1〜3の完了後 |
| 5 | `design-director` | `デザイン/<翌月>_デザイン.md` | 4の完了後 |
| 6 | `report-writer` | `レポート/YYYY-MM_レポート.md` | 4の完了後 |
| 7 | ディレクター | `送付/YYYY-MM_送付一式.md` | 6の完了後 |

1〜3は並行して動かしてよい。

各エージェントには次を明示して渡す：
- クライアント名 / 対象月
- 読むべきファイルの具体的なパス
- 出力先の具体的なパス

エージェントが「データが足りない」と返したら、**推測で埋めさせない**。
その工程は `未` のままにして、最後の報告に含める。

## 6. 品質チェック

成果物を読み、次を確認する。問題があれば担当エージェントに直させる。

- [ ] 数値がデータファイルと一致しているか
- [ ] 分析の結論と企画がつながっているか
- [ ] 企画とデザイン指示が食い違っていないか
- [ ] レポートに社内用語・他社名・ファイル名が混ざっていないか
- [ ] 効果を断定する表現・優良誤認になりうる表現がないか
- [ ] 前月レポートで約束したことに、今月のレポートが答えているか

## 7. 送付一式を作る

`90_テンプレート/送付一式.md` をもとに `送付/YYYY-MM_送付一式.md` を作る。

- 送付状の文面（そのままメール・チャットに貼れる形）
- 同梱物リスト（実際に送るファイルのパス）
- 送付前チェックリスト
- 次回打ち合わせで聞きたいこと

**送信はしない。** 人が確認してから送る。

## 8. 管理表を仕上げる

- 全工程が終わったら、その会社の「状態」を `確認待ち` にする
- 「送付」列は、送付一式ができた時点で `確認待ち`
- 「提出」列は触らない（人が更新する）

## 9. 報告

```
<クライアント名> / <対象月> 完了

できたもの
- 分析      <パス>
- 広告      <パスまたは「対象外」>
- 競合      <パス>
- 企画      <パス>
- デザイン  <パス>
- レポート  <パス>
- 送付一式  <パス>

要点3行
- <今月いちばん重要な事実>
- <その理由の仮説>
- <来月の打ち手>

確認してほしいこと
1. <判断が必要な点>
2. <データ不足で埋められなかった点>

このあと
1. レポートと送付一式を読む
2. 問題なければクライアントへ送付する
3. 「<クライアント名>は提出済み」と伝えてください（管理表を更新します）

次の会社を回す場合は、先に /clear を入力してください。
```

## 中断・再開について

利用上限などで途中終了した場合は、同じ `/monthly` をもう一度実行すれば、
管理表を見て `未` の工程から再開します。人が何かを覚えておく必要はありません。
